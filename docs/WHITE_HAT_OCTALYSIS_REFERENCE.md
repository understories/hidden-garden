# White-Hat Octalysis Design Reference for Leaderboards & UX Flows

This document defines the design principles to follow during the UX/UI design sprint.  
Its purpose is to ensure that all leaderboard and progression features follow **White-Hat Octalysis** motivational principles, while avoiding coercive or anxiety-driven Black-Hat patterns.

## 1. Design Goal

Build interfaces that promote:

- Long-term intrinsic motivation  
- Skill mastery  
- Empowerment through clear feedback loops  
- Psychological safety  
- Transparent, non-punitive progress structures  

All leaderboard-adjacent features should treat **growth, contribution, and learning** as primary motivators.

## 2. White-Hat Octalysis Principles to Apply

### Epic Meaning & Calling (CD1)
- Provide context for why actions matter.  
- Explain how user contributions strengthen the ecosystem.

### Development & Accomplishment (CD2)
- Show **personal progress** (levels, XP, rank improvements).  
- Ensure rules, scoring, and requirements are fully transparent.

### Empowerment of Creativity & Feedback (CD3)
- Display recent actions and proofs as qualitative activity, not just numerical score.  
- Provide clear next steps (e.g., challenges suited to level, opportunities to help).

### Positive Social Influence (CD5, White-Hat Mode)
- Highlight collaboration, helpfulness, and mentorship.  
- Surface community contributions that support others.

## 3. White-Hat Leaderboard Requirements

### A. Personal Progress Panel
Each leaderboard view should include:

- Current level  
- XP progress bar  
- Rank delta (improvements over time)  
- Recent accomplishments  
- Helpfulness indicators (sessions helped, validations, contributions)

### B. Leaderboard Table Structure
Leaderboard entries should include:

- Rank  
- Contribution Score  
- Helpful Sessions  
- Recent Proofs or Activity  

The user should always be clearly highlighted, even if far from the top.  
Provide contextual info such as:

- "Top X% this season"  
- "+Y ranks this week"

### C. Reward Structure
- Use earnable, **non-expiring**, **transparent** rewards.  
- Avoid exclusive or scarce tiers unless required.  
- Avoid punishment or loss of status as a mechanic.

### D. Copywriting Tone
- Supportive and informative.  
- No fear-based or urgency-based messaging.  
- Avoid red-warning visual language for "falling behind."

## 4. Black-Hat Patterns to Avoid

Unless explicitly requested for a specific mechanic, do not use:

- Rank-loss warnings ("You dropped 5 places")  
- Countdown timers or urgency pressure  
- "At risk", "Outside rewards", or shaming labels  
- High-contrast punitive UI  
- Expiring or exclusive reward tiers  
- Mystery rewards as primary motivation  
- Zero-sum status framing  

## 5. Decision Framework

Any leaderboard or progress-oriented design should be validated by asking:

- Does this promote mastery?  
- Is the progress visible, fair, and transparent?  
- Does this encourage helpful contribution?  
- Is the user supported, rather than pressured?  
- Are we avoiding coercive or fear-based cues?  

If any answer is negative, adjust toward a White-Hat direction.

## 6. Areas Where This Applies

This reference should guide:

- Leaderboard UI  
- Skill progression displays  
- Profile comparison views  
- Seasonal UX flows  
- Proof completion feedback  
- Achievement and badge systems  
- Session/helpfulness tracking UI  
- Notifications and toasts  
- Any rank, status, or progress-based mechanic  

## 7. White-Hat Safe Defaults

Default UX patterns should:

- Emphasize progress, not punishment  
- Offer clear next steps  
- Highlight contributions  
- Use transparent rules and criteria  
- Avoid urgency, shame, or exclusivity  
- Frame progress as part of a larger ecosystem narrative  
- Let users control visibility of sensitive metrics
